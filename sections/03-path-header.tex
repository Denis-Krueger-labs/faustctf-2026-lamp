\section{Path Header Overwrite}
\label{sec:path-header}

LAMP parsed the request-line path into \code{\textbackslash httpPath} and
validated it before processing headers. The header parser then constructed
TeX macro names from header names:

\begin{lstlisting}
\edef\name{\httpTransformHeaderName{\name}}
\expandafter\xdef\csname http\name\endcsname#1{\value}
\end{lstlisting}

A \code{Path} header consequently redefined the internal
\code{\textbackslash httpPath} macro. A request for the valid route \code{/}
could pass path validation, then replace that path with a traversal value.
The static handler appended \code{\textbackslash httpPath} to its
\code{/srv/www/} root and used the resulting path to serve a file.

\begin{lstlisting}
curl -g -6 --noproxy '*' --path-as-is \
  -H 'Path: /../../etc/hostname' \
  'http://[TARGET]:1337/'
\end{lstlisting}

This gave us file retrieval from outside the intended web root, subject to
what the service process could read. Later we used the same primitive to
retrieve files containing command output. The failure was the shared macro
namespace: validation checked the request-line path, while the handler
consumed the header's replacement value.
