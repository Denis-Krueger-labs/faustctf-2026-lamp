\section{From TeX Injection to Command Execution}
\label{sec:rce}

The working component-type value was:

\begin{lstlisting}
^^5cUseName{@@input}|"id>/x"
\end{lstlisting}

Here \code{\^{}\^{}5c} supplies the backslash,
\code{\textbackslash UseName\{@@input\}} resolves LaTeX's internal input
primitive, and the pipe form executes \code{id>/x} with shell escape enabled.
We did not need to insert command output into the document; redirecting it
to a file was enough. The earlier \code{Path} bug retrieved the result:

\begin{lstlisting}
curl -g -6 --noproxy '*' --path-as-is \
  -H 'Path: /../../x' \
  'http://[TARGET]:1337/'
\end{lstlisting}

The response contained \code{uid=0(root) gid=0(root) groups=0(root)}.
Execution was therefore confirmed as root inside the service container.

The component type's 32-byte database limit made this a constrained RCE:
the proof command fit, but a practical flag search did not. We needed a
short launcher for a longer command stored elsewhere.
