\section{Bypassing the 32-Byte Limit}
\label{sec:carrier-bypass}

Registration wrote the ship name to \code{/storage/<user>.tex} as a TeX
macro definition. The storage routine escaped backslashes, braces,
underscores, and carets, but allowed a newline. A ship name beginning
with a newline put a shell command on its own line in that file:

\begin{lstlisting}
ship=$'\n'"$shellcmd"

% Approximate saved file for user Q:
\def \shipname {
ls /storage>/x;:}
\end{lstlisting}

Although the surrounding TeX is not a useful shell program, the command
on the middle line runs when the file is passed to \code{sh}. A short
component payload launched it:

\begin{lstlisting}
^^5cUseName{@@input}|"sh /s*/Q*"
\end{lstlisting}

The glob shortened the path to the attacker-created \code{/storage/Q.tex}
file enough to fit the component field. The POST form used \code{\%20}
for the space in \code{sh /s*/Q*}; its parser did not turn a literal
\code{+} into a space. The carrier account's authenticated session was
then used to add the malicious component and trigger a render.

This separated storage from execution: the ship name held the long
command, while \code{typ} held only the launcher. The glob was a compact
competition shortcut; extra matching paths could make it unreliable.
