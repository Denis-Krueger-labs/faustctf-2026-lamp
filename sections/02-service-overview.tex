\section{Service Overview}
\label{sec:service-overview}

The entry point, \code{/srv/main.tex}, configured Redis and MariaDB, loaded
custom HTTP handling and authentication middleware, then called
\code{\textbackslash httpServe\{\}}. Request lines, headers, POST values,
database rows, and stored files all entered the TeX process. With shell escape
enabled, TeX also invoked the MariaDB client through \code{\textbackslash write18}.

Redis held sessions and account data; MariaDB held ships and components.
Registration wrote each ship name to a per-user TeX file under
\code{/storage}. Viewing a ship included that file again:

\begin{lstlisting}
\immediate\openout\shipfile=/storage/\postusername{}
\store{\shipname}{\postshipname{}}
\immediate\closeout\shipfile{}

% During a later request:
\input{/storage/\username{}.tex}
\end{lstlisting}

The relevant trust boundaries were HTTP to TeX, database to TeX, and stored
text to a file that the service later interpreted. The next sections show
where those boundaries failed.
