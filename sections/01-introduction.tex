\section{Introduction}
\label{sec:introduction}

LAMP was a ship-building web service in FAUST CTF 2026. Users could register,
name a ship, add components, and view the result. Unusually, XeLaTeX handled
much of the HTTP and application logic. The service started it with:

\begin{lstlisting}
xelatex -8bit --shell-escape /srv/main.tex
\end{lstlisting}

We found a chain from client-controlled input to command execution as root
\emph{inside the LAMP container}. This does not establish root access to the
underlying Vulnbox host. The chain combined a \code{Path} header overwrite,
stored TeX injection through component types, and a newline injection in
persisted ship names that overcame a 32-byte payload limit. The same path
also let us retrieve command output and checker flags.

This report follows the code paths and payloads we used during the live
competition, then describes the observed results and fixes.
